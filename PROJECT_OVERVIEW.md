# Meeting Summarizer — из чего состоит и что умеет


> **Язык:** внутренний документ проекта, намеренно только на русском — в отличие
> от поставляемых пользователю доков (README, ARCHITECTURE, DEPLOYMENT, MCP_USAGE,
> google-sheets, WHISPER_ENGINES_COMPATIBILITY), которые есть на обоих языках.
Материал для презентации. Версия 1.2.1.

**Что это.** Локальный инструмент, который превращает запись встречи в структурированное
саммари и подробный анализ: транскрибация → саммари → анализ из 11 фич → экспорт. Работает
офлайн на своей машине; облако — по желанию.

**Главный архитектурный принцип.** Один проверенный Python-бэкенд, два независимых фронтенда
над ним. Фронтенды не содержат логики обработки: они собирают аргументы командной строки и
запускают модули бэкенда **отдельными процессами**, читая построчный JSON-прогресс. Отсюда
три следствия: интерфейс физически не может испортить код транскрибации; тяжёлые задачи не
блокируют UI; десктоп и веб-кабинет всегда имеют одинаковый набор возможностей.

## 1. Компоненты

### Общий бэкенд (`backend/`) — на нём всё держится

| Модуль | За что отвечает |
|---|---|
| `processor.py` | Главный модуль транскрибации: извлекает аудио через ffmpeg, выбирает движок и отдаёт текст. Стримит прогресс JSON-строками. |
| `engines_registry.py` | Реестр движков и моделей: какие есть, что скачано, какой путь, что показывать под язык. Выбор движка идёт через реестр, а не через цепочки `if`. |
| `processing/engines/*.py` | По адаптеру на движок: `openai_whisper`, `faster_whisper`, `whisperx`, `vosk`, `sherpa_onnx`, `whispercpp`, `funasr`, `sherpa_extra`. Добавить движок = добавить адаптер. |
| `ai_client.py` | Единая точка выхода к ИИ: локальный HTTP-эндпоинт, облако по ключу, локальный агент-CLI. Плюс чанкинг длинных транскриптов (map-reduce). |
| `models_cli.py` + `download_model.py` | Скачивание и обновление моделей движков с докачкой при обрыве. |
| `url_download.py` | Загрузка видео по ссылке (yt-dlp), с автоподхватом cookies браузера для YouTube. |
| `rag.py` + `embeddings.py` | База знаний: векторное хранилище chromadb + эмбеддинги (по умолчанию офлайн-модель). |
| `gpu_handoff.py` | Освобождение видеопамяти: останавливает локальную LLM (свою и встроенную) на время транскрибации и возвращает их обратно. |
| `local_ai_watchdog.py` | Сторож встроенной модели: переподнимает её, когда она упала, и молчит, пока идёт транскрибация. |
| `local_ai.py` | Встроенный ИИ по требованию: скачивает актуальную сборку llama.cpp и модель, запускает сервер. |
| `mcp_server.py` | MCP-сервер: отдаёт архив встреч наружу как инструменты для ИИ-агентов. |
| `whisperx_patch.py` | Патч совместимости WhisperX. |

### Десктоп (`desktop/app/`) — PySide6

**Ядро (`core/`)** — оркестрация:

| Модуль | За что отвечает |
|---|---|
| `pipeline.py` | Сердце приложения: очередь задач и раннер, ведущий файл по этапам `аудио → транскрибация → саммари → анализ`. По раннеру на файл, поэтому параллельные задачи не путаются. Считает время каждого этапа. |
| `history.py` | Хранилище истории: у каждого файла свой id, к нему привязаны статус и версии артефактов. |
| `worker.py` | Обёртки над процессами и потоками, чтобы интерфейс не подвисал. |
| `recorder.py` | Запись с микрофона сразу в формат, нужный распознаванию (16 кГц моно WAV). |
| `models.py` | Статусы задач и их подписи. |
| `device.py`, `metrics.py`, `trace.py`, `queue_manager.py` | Определение CUDA, метрики системы, профиль обработки, расчёт числа потоков. |

**Интерфейс (`ui/`)**: `main_window.py` (главное окно: загрузка, очередь, статус, результаты),
`settings_dialog.py`, `trim_dialog.py` (нарезка), `recorder_dialog.py` (диктофон),
`local_ai_dialog.py` (встроенный ИИ), `speakers_dialog.py`, `analysis_widget.py` (панели
анализа), `rag_dialog.py`, `search_dialog.py`, `diagnostics_dialog.py`, `stats_dialog.py`,
`theme.py` (оформление).

**Адаптеры (`backend/`, без Qt, поэтому легко тестируются)**: `transcription.py`,
`summarization.py`, `analysis.py` (сборка команд к бэкенду), `exporter.py` (экспорт во все
форматы), `media.py` (нарезка через ffmpeg), `templates.py` (шаблоны промптов),
`speakers.py`, `obsidian.py`, `gsheets.py`, `textsearch.py`.

### Веб-кабинет (`server/`) — FastAPI

Многопользовательский вариант: `api/routes/` (auth, meetings, settings, engines, rag,
templates, queue), `processing/worker.py` (тот же пайплайн, что и в десктопе),
`auth/` (JWT), SQLite, статический дашборд на Tailwind (`web/`). Приём встреч тот же,
что и в десктопе: файл, ссылка или запись с микрофона в браузере (`MediaRecorder`;
браузер даёт микрофон только по HTTPS или на localhost). Длинную запись можно нарезать
на отдельные встречи прямо в браузере — по волне, посчитанной на сервере.

### Как это упаковано

`desktop/packaging/build.py` собирает две раздачи: **min** (0.32 ГБ, исходники + установщик)
и **full** (12.3 ГБ, со встроенным Python, всеми зависимостями и моделями — распаковал и
работаешь без интернета).

min не требует ничего заранее: если на машине нет Python, `INSTALL.bat` предложит поставить
его сам — 3.11 с python.org, с проверкой подписи Python Software Foundation и только для
текущего пользователя (`desktop/packaging/bootstrap_python.ps1`). Дальше установщик сканирует
машину и ставит только отмеченное.

## 2. Все возможности проекта

### Ввод материала
- **Перетаскивание и выбор файлов** — MP4/AVI/MOV/MKV/WebM (`ui/main_window.py`, `core/history.py`)
- **Добавление по ссылке** — YouTube или файл-сервер, с автоподхватом cookies для закрытых видео (`backend/url_download.py`, `ui/main_window.py`)
- **Запись с микрофона** — встроенный диктофон с выбором устройства, индикатором уровня и паузой (`core/recorder.py`, `ui/recorder_dialog.py`)
- **Нарезка одной записи на несколько встреч** — плеер предпросмотра и шкала с перетаскиваемыми метками; каждый фрагмент становится **отдельной задачей** со своим саммари и анализом (`ui/trim_dialog.py`, `backend/media.py`)

### Транскрибация
- **7 движков на выбор** — OpenAI Whisper, Faster-Whisper, WhisperX, Vosk, sherpa-onnx, whisper.cpp, FunASR (`backend/processing/engines/*`, `backend/engines_registry.py`, `backend/processor.py`)
- **Скачивание и обновление моделей из интерфейса**, с докачкой после обрыва (`backend/models_cli.py`, `backend/download_model.py`, `ui/settings_dialog.py`)
- **Дополнительные community-модели** (GigaAM RU, Moonshine EN) — ставятся отдельно, в сборку не входят (`backend/processing/engines/sherpa_extra_engine.py`)
- **Разделение по спикерам** — офлайн sherpa-onnx по умолчанию (без токена), опционально pyannote (`backend/processing/engines/whisperx_engine.py`)
- **Переименование спикеров и правка реплик** после распознавания (`ui/speakers_dialog.py`, `backend/speakers.py`)
- **Автоопределение CUDA** с откатом на процессор и подбором числа потоков (`core/device.py`, `core/queue_manager.py`)
- **Словарь терминов** — подсказка движку по именам и аббревиатурам (`backend/transcription.py`)

### Саммари и анализ
- **Саммари по настраиваемому промпту** (`backend/ai_client.py`, `backend/summarization.py`)
- **13 шаблонов промптов** под типы встреч × RU/EN, у каждого вариант с указанием спикеров, плюс свои шаблоны с импортом/экспортом (`backend/templates.py`, `ui/settings_dialog.py`)
- **Анализ из 11 фич** — задачи, тональность, категория, ключевые темы, риски, цитаты, технологии, открытые вопросы, рекомендации, вопросы к следующей встрече, формальный протокол ГОСТ/ISO (`backend/analysis.py`, `ui/analysis_widget.py`)
- **Выбор источника анализа** — по саммари (быстро) или по транскрипту (полнее) (`backend/analysis.py`, `core/pipeline.py`)
- **Язык вывода отдельно от языка записи** — английская встреча, русское саммари (`backend/summarization.py`)
- **Чанкинг длинных встреч** — отключаемый, для моделей с малым контекстом (`backend/ai_client.py`)
- **Контекстная память** — подмешивает саммари прошлых встреч того же проекта (`core/pipeline.py`)
- **Правка транскрипта и перегенерация** — исправил текст, получил новую версию саммари и анализа (`ui/main_window.py`, `core/pipeline.py`)
- **История версий** — все версии саммари и анализа сохраняются и переключаются (`core/history.py`, `ui/main_window.py`)

### Четыре способа подключить ИИ
- **Свой локальный эндпоинт** — llama.cpp, LM Studio, Ollama, любой OpenAI-совместимый (`backend/ai_client.py`)
- **Облако по ключу** — OpenAI, Anthropic, Google, xAI, Qwen, Mistral, DeepSeek + полностью кастомный запрос (`backend/ai_client.py`, `ui/settings_dialog.py`)
- **Локальные агенты** — Claude Code, Codex, Hermes или любой CLI, читающий stdin (`backend/ai_client.py`)
- **Встроенный ИИ по требованию** — приложение само скачает движок и модель под объём видеопамяти и запустит (`backend/local_ai.py`, `ui/local_ai_dialog.py`)
- **Освобождение видеопамяти** — на время транскрибации локальная модель выгружается и потом возвращается (`backend/gpu_handoff.py`, `core/pipeline.py`)

### Знания и поиск
- **Семантическая база знаний** по встречам, работает офлайн (`backend/rag.py`, `backend/embeddings.py`, `ui/rag_dialog.py`)
- **Текстовый поиск по транскриптам** (`backend/textsearch.py`, `ui/search_dialog.py`)
- **MCP-сервер** — ИИ-агент сам ходит в архив встреч: список, транскрипт, саммари, анализ, поиск буквальный и семантический (`backend/mcp_server.py`)

### Экспорт
- **Шесть форматов** — txt, md, json, html, pdf, docx (`backend/exporter.py`)
- **Красивый HTML-отчёт анализа** — карточки, бейджи приоритетов, полосы тональности (`backend/exporter.py`)
- **Экспорт в Obsidian** — заметки, индекс встреч, People/Topics, Dataview (`backend/obsidian.py`)
- **Google Sheets** — строка после каждой обработки через Apps Script (`backend/gsheets.py`)
- **Файлы по спикерам** — отдельный текст на каждого участника (`backend/speakers.py`)

### Интерфейс и эксплуатация
- **Очередь с параллельной обработкой**, удаление из очереди, отмена (`core/pipeline.py`, `ui/main_window.py`)
- **Время по каждому этапу** — сколько заняли аудио, транскрибация, саммари, анализ (`core/pipeline.py`, `ui/main_window.py`)
- **Диагностика** — CPU/ОЗУ/GPU, профиль обработки диаграммой, сравнение движков A-B, логи (`ui/diagnostics_dialog.py`, `core/metrics.py`, `core/trace.py`)
- **Статистика по встречам** (`ui/stats_dialog.py`)
- **Тёмная и светлая темы, русский и английский интерфейс** (`ui/theme.py`, все окна)

### Второй фронтенд
- **Веб-кабинет** — многопользовательский, вход по JWT, тот же набор функций через браузер (`server/api/*`, `server/processing/worker.py`, `server/web/*`)

### Качество и поставка
- **46 наборов автотестов**, 1395 проверок — от протокола MCP до нарезки ffmpeg (`desktop/_selftest_*.py`, `server/_selftest_*.py`)
- **Две раздачи** — min 0.32 ГБ и full 12.3 ГБ (работает без интернета) (`desktop/packaging/build.py`)

## 3. Зависимости

Две изолированные среды. Тяжёлое (распознавание, ИИ) живёт во **встроенном Python**
(`backend/python`), веб-слой — в своём **лёгком venv**: серверу не нужен ни torch, ни движки,
он вызывает встроенный рантайм подпроцессом. Поэтому веб-кабинет ставится за секунды.

### Не-пакетные ресурсы

| Ресурс | Как поставляется |
|---|---|

| **Модели распознавания** | Скачиваются по требованию в `resources/<движок>_models/`; в сборке **full** уже лежит по одной medium-модели на движок |

### Внешние сервисы (все необязательные)

Облачные ИИ (OpenAI, Anthropic, Google, xAI, Qwen, Mistral, DeepSeek) — по ключу;
Google Sheets — через Apps Script, разворачивает сам пользователь; HuggingFace — источник
моделей; GitHub Releases — источник сборок llama.cpp. **Без всего этого приложение полностью
работоспособно офлайн.**

## 4. Что стоит показать вживую

1. Добавить запись с несколькими встречами → нарезать на фрагменты → получить отдельные саммари.
2. Показать переключение способа ИИ: свой сервер / облако / агент / встроенный.
3. Открыть HTML-отчёт анализа — он выглядит как готовый документ.
4. Задать вопрос ИИ-агенту по архиву встреч через MCP.
