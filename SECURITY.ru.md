## Как сообщить об уязвимости

**Не заводите публичный issue про уязвимость.** Issue виден всем с момента
создания — вместе с описанием того, как эксплуатировать проблему.

Используйте приватный канал GitHub: вкладка **Security** → **Report a
vulnerability**. Так создаётся приватный advisory, видимый только мейнтейнерам.

> Если такой ссылки в репозитории нет, значит приватные сообщения об уязвимостях
> ещё не включены (по умолчанию на GitHub они **выключены**, в том числе для
> репозиториев, созданных до включения общего переключателя в аккаунте).
> Включается в *Settings → Code security → Private vulnerability reporting*.

Первый ответ — ориентировочно в течение недели. Программы вознаграждений нет.

## Что НЕ прикладывать

Смысл отчёта — в баге, а не в ваших данных. **Никогда** не прикладывайте:

- реальные API-ключи и токены (OpenAI/Anthropic/Google/xAI/Qwen/Mistral/DeepSeek,
  HuggingFace, `JWT_SECRET_KEY`, содержимое `config/.jwt_secret`);
- URL вашего Google Apps Script — любой, у кого он есть, сможет писать в вашу
  таблицу;
- `config/server.db`, `config/history.json` и вообще файлы из `transcripts/`,
  `uploads/`, `recordings/`, `rag_knowledge_base/` — там реальное содержимое
  встреч;
- полные логи, не прочитав их: в них попадают пути, названия встреч и имена
  учётных записей.

Затирайте чувствительное или описывайте форму данных вместо вставки. Если для
воспроизведения действительно нужна запись — напишите об этом, договоримся о
канале.

## Область

Проект работает **на вашей машине или вашем сервере**. Мейнтейнеры не держат
никакого сервиса, атаковать нечего — и, пожалуйста, не атакуйте чужие установки.

В области: аутентификация и работа с сессиями в веб-кабинете, изоляция между
аккаунтами, path traversal в загрузке/экспорте/скачивании, инъекции в
подпроцессы транскрибации и ИИ, политика хостов при приёме по URL, утечки
секретов в логи и экспорты, проверки прав на admin-эндпоинтах.

Вне области: всё, что требует физического или административного доступа к машине,
где запущено приложение; отказ в обслуживании гигантскими файлами; уязвимости в
сторонних компонентах (сообщайте в апстрим — см.
[THIRD-PARTY-NOTICES.ru.md](THIRD-PARTY-NOTICES.ru.md)).

## Эксплуатационные замечания для веб-кабинета

- В продакшене задавайте `JWT_SECRET_KEY` явно. Без него сервер генерирует
  случайный секрет в `config/.jwt_secret` при старте: каждый перезапуск
  инвалидирует сессии, а сам файл нужно беречь как пароль.
- **Первая учётная запись на чистой установке становится администратором.**
  Зарегистрируйте её сами, прежде чем открывать порт кому-то ещё.
- Ставьте за TLS. `TRUSTED_PROXIES` задаёт, кому позволено выставлять
  `X-Forwarded-*`; значение по умолчанию доверяет только локальному прокси.
- Полное руководство — [server/DEPLOYMENT.ru.md](server/DEPLOYMENT.ru.md).
